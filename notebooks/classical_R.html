1. Données

1.1 Lecture du cache et vérification avec quantmod

Pour comparer R et Python sur des données strictement identiques, on lit le même cache CSV que Python (data/raw/, téléchargé avec yfinance). Yahoo recalcule l’Adj Close à chaque dividende : deux téléchargements à des dates différentes ne donneraient pas les mêmes prix. On utilise ensuite quantmod pour vérifier que Yahoo renvoie bien les mêmes prix aujourd’hui. Le to de getSymbols exclut la date de fin : on passe donc le lendemain du dernier jour de la période.

read_cache <- function(ticker) {
  f <- here("data", "raw", paste0(gsub("=", "_", ticker), ".csv"))
  d <- read.csv(f, check.names = FALSE)
  xts(d[["Adj Close"]], order.by = as.Date(d$Date))
}

moments <- function(x) {
  m <- mean(x); s <- sd(x); z <- (x - m)
  # Skewness et kurtosis « population » (mêmes définitions que scipy, valeurs par défaut).
  sk <- mean(z^3) / mean(z^2)^1.5; ku <- mean(z^4) / mean(z^2)^2 - 3
  c(moyenne = m, ecart_type = s, skewness = sk, exces_kurtosis = ku,
    jarque_bera = unname(jarque.bera.test(x)$statistic))
}

stl_strength <- function(x, period) {
  s <- stl(ts(as.numeric(x), frequency = period), s.window = 7, robust = TRUE)$time.series
  c(F_T = max(0, 1 - var(s[, "remainder"]) / var(s[, "trend"] + s[, "remainder"])),

2.4 Valeurs aberrantes (IQR glissant sur les 63 jours précédents, k = 3)

count_outliers <- function(x, w = cfg$features$outlier_window, k = cfg$features$outlier_iqr_k) {
  x <- as.numeric(na.omit(x))
  q1 <- rollapply(x, w, quantile, probs = 0.25, align = "right", fill = NA)
  q3 <- rollapply(x, w, quantile, probs = 0.75, align = "right", fill = NA)
  q1 <- c(NA, head(q1, -1)); q3 <- c(NA, head(q3, -1))   # décalage d'un jour : seuil calculé sur le passé
  iqr <- q3 - q1
  sum((x < q1 - k * iqr) | (x > q3 + k * iqr), na.rm = TRUE)
}

2.5 Stationnarité : ADF, KPSS, Zivot-Andrews

urca ne fournit pas de p-values pour ADF et KPSS, seulement des valeurs critiques. Pour comparer les statistiques à Python, on impose les mêmes nombres de retards : ADF avec choix par AIC jusqu’à ⌈12 (n/100)^(1/4)⌉ = 27 retards, comme statsmodels ; KPSS avec le nombre de retards trouvé par statsmodels, puis avec la règle par défaut de urca.

adf <- function(x, type) {
  t <- ur.df(as.numeric(x), type = type, lags = maxlag, selectlags = "AIC")
  # Nombre de retards retenus = lignes de la régression de test moins constante, niveau retardé et tendance.
  c(stat = unname(t@teststat[1]), retards = nrow(t@testreg$coefficients) - 1 - (type != "none") - (type == "trend"),
    VC5 = unname(t@cval[1, "5pct"]))
}
kpss <- function(x, type, lag) {
  t <- ur.kpss(as.numeric(x), type = type, use.lag = lag)

}

4.2 Explication des écarts

Bilan. Sur 88 grandeurs comparées, 68 sont identiques (écart relatif < 0,1 %) et 14 très proches (< 2 %). Aucune conclusion du projet ne change entre R et Python. Les données, le découpage, les statistiques descriptives, les valeurs aberrantes, KPSS, Zivot-Andrews, les ARIMA de petit ordre, le SARIMA, les coefficients du VAR(1), le Portmanteau, Johansen et le VECM coïncident à la précision numérique près.

Les écarts restants ont tous une cause identifiée et vérifiée :

Écart Cause Preuve
ADF du log-prix : −0,948 en R contre −0,971 en Python, avec le même nombre de retards (18) urca estime le modèle retenu sur l’échantillon raccourci par le retard maximal testé (27). statsmodels le ré-estime sur l’échantillon le plus long permis par le retard choisi (18), soit 9 observations de plus. Avec 18 retards imposés, R donne −0,9714, comme Python. Conclusion identique : racine unitaire non rejetée (valeur critique à 5 % : −2,86).
Engle-Granger : −4,41 en R contre −3,46 en Python, avec le même nombre de retards (19) Même cause que pour l’ADF. Ici l’effet est grand, parce que les 8 observations en plus ou en moins tombent en janvier 2016, quand l’écart à l’équilibre était au plus haut (figure 11 du notebook Python). Avec 19 retards imposés, R donne −3,4565, comme Python. Les deux statistiques dépassent la valeur critique à 5 % (−3,34). L’écart montre surtout que ce test est sensible aux toutes premières observations, ce qui confirme le diagnostic de cointégration fragile.
ARIMA(3,1,2) : log-vraisemblance −4 511,1 en R contre −4 504,6 en Python La vraisemblance de ce modèle a plusieurs maxima locaux, conséquence de la quasi-annulation des racines AR et MA (§3.1 Python). Partant d’un autre point initial, l’optimiseur de R s’arrête sur un sommet moins haut. Démarré aux coefficients de Python, R retrouve exactement −4 504,631.
auto.arima (AIC) : ARIMA(5,1,0) en R contre ARIMA(3,1,2) en Python Conséquence directe de la ligne précédente : R ayant mal estimé l’ARIMA(3,1,2), le meilleur AIC qu’il voit est celui de l’ARIMA(5,1,0), qui vaut 9 033,74 dans les deux langages. Ce désaccord renforce la décision du §3.1 : le choix de l’AIC est instable, alors que celui du BIC (ARIMA(0,1,0)) est identique dans les deux langages.
Ordre du VAR selon le BIC : 1 en R contre 0 en Python vars::VARselect ne teste que les ordres 1 à 10 et ne peut pas choisir 0. En Python, le BIC choisit 0 parce que cet ordre est disponible. Le plus petit ordre testé par VARselect est 1. Les autres critères (AIC 9, HQ 7, FPE 9) coïncident.
Paramètres GARCH (écarts de 0,3 à 1,6 %) et log-vraisemblance (environ 0,3 point de moins en R) La variance initiale de la récurrence diffère : arch part d’une moyenne pondérée des premiers rendements au carré (« backcast », 4,48), rugarch de la moyenne de tous les rendements au carré (3,18). Aux paramètres de Python, rugarch calcule une log-vraisemblance de −4 045,62. Avec la convention de rugarch, Python trouve −4 045,62 aussi. Les tests sur les résidus standardisés (ARCH-LM 14,0 contre 14,5 ; KS p = 0,46 contre 0,45) ne diffèrent que par ces petits écarts de paramètres.
p-values du test de Granger (écart relatif de 0,1 à 0,3 %) vars::causality teste le système complet (ddl du dénominateur : 2 × 2 257 = 4 514). Le test Python porte sur l’équation seule (2 257 ddl). Même décision dans tous les cas. Avec HC3, l’écart tombe à 0,03 %.
Force de tendance STL, période 252 : 0,8676 contre 0,8686 Le STL robuste de R fait 1 itération interne par passe robuste, celui de statsmodels 2. Saisonnalité nulle dans les deux cas.

Conclusion. Les deux implémentations donnent les mêmes résultats lorsque les mêmes réglages sont imposés. Les seuls écarts proviennent de conventions par défaut différentes : échantillon de sélection des retards, point de départ de l’optimiseur, variance initiale du GARCH, ordres testés par VARselect. Ces écarts ne modifient aucune décision du projet : - d = 1 ; - marche aléatoire retenue ; - pas de prédictibilité croisée robuste ; - cointégration faible ; - GJR(1,1) de Student, avec une persistance d’environ 0,999.

Ils apportent même deux informations utiles : la fragilité de l’ARIMA(3,1,2), dont la vraisemblance a plusieurs maxima, et celle du test d’Engle-Granger, sensible aux premières observations.
